# Plan: 점검 관리 페이지 UX 개선

## 1. 개요

### 1.1 기능명
inspection-ux-improvement (점검 관리 페이지 사용성 개선)

### 1.2 배경
현재 `/inspections` 페이지와 하위 페이지들은 기능적으로 동작하지만, 사용성 측면에서 다음과 같은 문제점이 발견되었다:

**메인 페이지 (`/inspections`)**
- 통계 카드 4개가 단순 숫자만 표시 → 비교/추이 정보 없음
- 최근 제출 테이블의 페이지네이션이 불필요 (최대 5건 고정인데 페이지네이션 UI가 보임)
- 빠른 이동 카드 2개가 하단에 작게 배치 → 메인 기능 접근성 낮음
- 수탁사명이 표시되지 않아 어떤 수탁사의 체크리스트인지 확인 불가
- 빈 상태(Empty state)일 때의 안내가 부족

**체크리스트 목록 (`/inspections/checklists`)**
- 컬럼이 9개로 과다 → 작은 화면에서 가독성 저하
- 상태 필터만 있고 검색 기능 없음
- 수탁사명 컬럼이 없어 어떤 수탁사의 체크리스트인지 모름
- "만료됨" 기한이 눈에 잘 띄지 않음

**체크리스트 상세 (`/inspections/checklists/[id]`)**
- 페이지가 매우 길어 스크롤이 과다 (1100줄 단일 컴포넌트)
- 상단 정보(링크, 기한, 작성자)가 분산되어 있어 한눈에 파악 어려움
- 스코어 패널에서 N/A가 -1%로 표시되는 버그
- 아코디언이 모두 펼쳐져 있어 80개 항목이 한꺼번에 노출될 수 있음

**템플릿 관련 페이지**
- 템플릿 생성이 JSON 붙여넣기만 지원 → 파일 업로드 미지원
- 템플릿 상세에서 항목 수 파악이 어려움 (아코디언 중첩)

**공통**
- MUI Warning 3건 발생 (out-of-range value for Select)
- 사이드바에서 현재 하위 페이지 위치를 알 수 없음 (점검 관리 > 체크리스트 등)

### 1.3 목표
- 점검 관리 페이지의 정보 접근성과 가독성을 개선한다
- 핵심 워크플로우(체크리스트 생성 → 전달 → 제출확인 → 검토)를 직관적으로 만든다
- 불필요한 UI 요소를 제거하고 중요한 정보를 강조한다
- MUI 콘솔 경고를 해결한다

### 1.4 범위

#### In-Scope
1. 점검 메인 페이지 레이아웃 개선
2. 체크리스트 목록 페이지 검색/필터 개선 + 수탁사명 표시
3. 체크리스트 상세 페이지 정보 구조 개선
4. 빈 상태(Empty State) UI 추가
5. N/A 퍼센트 버그 수정
6. MUI Select 경고 수정
7. 템플릿 생성 시 파일 업로드 지원

#### Out-of-Scope
- 사이드바 네비게이션 구조 변경 (별도 기능)
- 권한/인증 시스템
- 새로운 API 엔드포인트 추가
- 모바일 반응형 최적화

## 2. 사용자 시나리오

### 2.1 관리자 핵심 워크플로우
1. `/inspections` 진입 → 전체 현황 파악 (통계 + 최근 활동)
2. "검토 필요" 항목 확인 → 즉시 해당 체크리스트로 이동
3. 체크리스트 상세에서 수탁사 제출 내용 확인 → 검토/반려 처리
4. 새 체크리스트 생성 → 수탁사에 링크 전달

### 2.2 개선 후 사용자 경험
- 메인 페이지에서 "검토 대기 N건" 등 액션이 필요한 항목을 바로 파악
- 체크리스트 목록에서 수탁사명으로 검색 가능
- 상세 페이지에서 핵심 정보(점수, 상태, 미흡항목)를 상단에서 즉시 확인
- 빈 상태에서 다음 행동을 안내받음

## 4. 기술적 고려사항

### 4.1 수탁사명 표시
- 현재 체크리스트 API 응답에 `trusteeId`만 있고 수탁사명이 없음
- 백엔드에서 체크리스트 조회 시 수탁사 정보를 join하여 반환하도록 수정 필요
- 또는 프론트엔드에서 수탁사 목록을 별도 조회하여 매핑

### 4.2 검색 기능
- 기존 API의 `search` 파라미터 활용 가능 여부 확인 필요
- 프론트엔드 debounce 적용 (300ms)

### 4.3 컴포넌트 분리
- 체크리스트 상세 페이지가 1100줄 → 500줄 이하로 분리 목표
- `ChecklistInfoCard`, `ChecklistCategoryView`, `ChecklistActionBar` 등

### 4.4 Empty State
- `@trustee/ui`에 EmptyState 공통 컴포넌트 추가 검토
- 또는 각 페이지에서 인라인으로 처리

## 5. 영향 범위
- **프론트엔드**: `frontend/web/src/app/(dashboard)/inspections/` 하위 전체
- **컴포넌트**: `frontend/web/src/components/ScorePanel.tsx`
- **백엔드**: 체크리스트 목록 API에 수탁사명 포함 (변경 필요 시)
- **UI 패키지**: 빈 상태 컴포넌트 (선택)

## 6. 성공 지표
- MUI 콘솔 경고 0건
- 체크리스트 상세 페이지 컴포넌트 500줄 이하
- 메인 페이지에서 "검토 필요" 항목까지 클릭 2회 이내
- 빈 상태에서 다음 액션 안내가 표시됨
